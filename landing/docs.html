Getting Started

1. Install

Download the installer for your platform from the download section:

  • Windows: Sunday-UserSetup-1.0.0-beta.1-win-x64.exe (per-user install, recommended) or Sunday-Setup-1.0.0-beta.1-win-x64.exe (all users)
  • macOS: Sunday-1.0.0-beta.1-mac-arm64.dmg (Apple Silicon)
  • Linux: Sunday-1.0.0-beta.1-linux-x64.tar.gz

Alternatively, install the sunday-agent extension into stock VS Code from the .vsix file via Extensions → … → Install from VSIX.

2. Sign in

On first launch, choose Sign in with GitHub, Google, or Microsoft. This creates your Sunday session and activates the free tier — 200 AI requests per day, no API key, no credit card. Your credentials are stored in your OS keychain, never in plain files.

3. Run your first agent task

  1. Open a project folder (or create an empty one to experiment).
  2. Open the Sunday Agent panel from the activity bar.
  3. Type a task, for example: Create a Python script that renames all .txt files in this folder with today's date prefix, and add a README explaining it.
  4. Watch the agent plan, work, and report back. Review the diff before accepting.

New to agent workflows? The 5-minute tutorial walks through this exact flow with screenshots of what to expect at each step.

Architecture overview

Sunday is a VS Code fork with four cooperating layers:

The IDE (this app)

The full editor: workbench, terminal, debugger, and all standard VS Code functionality, plus Sunday's agent panels (chat, swarm Kanban, Mission Control, Artifacts, Second Brain). Built from the VS Code open-source codebase and packaged per-platform via CI.

The extension (sunday-agent)

The agent brain that also runs inside stock VS Code. It handles prompt orchestration, tool calls (file edits, terminal commands, browser control), conflict detection between parallel agents, and the local memory store. Installable standalone from the .vsix.

The daemon (sundayd)

A small local background service that outlives the editor window. It owns scheduled tasks (cron for agents), long-running agent processes, and the Mission Control registry. Because it is separate from the UI process, a scheduled 3am task runs even with the IDE closed, and a renderer crash never takes your agents down with it.

The hosted gateway

The cloud service that makes zero-config possible. It holds provider API keys server-side, enforces per-plan quotas and rate limits, tracks coding streaks, and issues sessions on OAuth sign-in. Your code and prompts are proxied, never stored — see Security model.

Provider setup

Sunday is API-first: no model runs on your machine. You have two ways to get inference:

Option A — Sunday hosted gateway (default, zero config)

Sign in and go. The gateway routes your requests across its provider pool (OpenRouter and Groq backends). Your plan's daily quota applies. This is the recommended path for almost everyone.

Option B — Bring your own key (BYOK)

Prefer your own provider account? Add your key in Settings → Sunday → Providers:

  • OpenRouter — paste an OpenRouter API key; you get access to their full model catalog and pay OpenRouter directly.
  • Groq — paste a Groq API key for their high-speed inference endpoints.

With BYOK, requests bypass Sunday's quotas entirely — your only limits are your provider's. Keys are stored in the OS keychain, never in settings files or logs.

Ollama fallback: a local Ollama endpoint can be configured as a fallback provider for offline-capable models. It is opt-in and off by default.

Security model

  • OAuth sign-in: GitHub, Google, or Microsoft. Sunday never sees your password; sessions are short-lived and refreshable.
  • Key storage: provider keys and session tokens live in the OS keychain (Windows Credential Manager, macOS Keychain, Linux Secret Service).
  • Gateway privacy: prompts are proxied to providers, never stored. Rate-limit counters are the only persisted per-user data, kept in durable storage.
  • Agent sandboxing: file edits are scoped to your open workspace; terminal commands run with your user privileges and are shown before execution in confirm mode. The browser agent runs in an isolated Chromium profile.
  • Anti-abuse: max 2 distinct accounts per machine per 24 hours on the free tier; anomaly detection on request patterns.
  • Open source: the client, extension, and daemon are Apache-2.0. You can audit exactly what runs on your machine.

FAQ

Is Sunday really free?

Yes. The free tier gives you 200 AI requests per day through the Sunday hosted gateway — real models, no credit card, no expiry. Paid plans exist for higher limits, parallel agents, and browser sessions.

Do I need my own API key?

No. Sign in with GitHub, Google, or Microsoft and the hosted gateway handles inference. You can optionally add your own OpenRouter or Groq key (BYOK) if you prefer to pay a provider directly and bypass Sunday quotas.

How is Sunday different from VS Code + an AI extension?

Sunday is a full fork, which lets it integrate agents at the workbench level: parallel agent orchestration with conflict detection, a persistent daemon for scheduled tasks, Mission Control, and deep Second Brain memory. An extension alone can't own scheduling, cross-agent coordination, or workbench-level UI the same way.

What happens when I hit my daily quota?

Requests pause until the quota resets at midnight (your timezone). Streak bonuses (+100/day at 7 days, +500/day at 30 days) raise your effective limit. Upgrading a plan or adding a BYOK key removes the cap immediately.

Can I use Sunday offline?

The editor itself works offline like any VS Code fork. AI features need inference — either the hosted gateway/BYOK (online) or a locally configured Ollama endpoint as fallback.

Which platforms are supported?

Windows (x64), macOS (Apple Silicon), and Linux (x64). The sunday-agent VSIX also runs inside stock VS Code on any platform VS Code supports.

How do updates work?

Sunday checks for updates on startup. One click installs them. Beta-channel installs automatically receive prerelease builds, so testers get fixes fast.

Is my code sent to the cloud?

Only the context needed for inference is sent to the model provider — the same as any AI coding assistant. The gateway proxies requests without storing prompts or code. Second Brain memories stay on your machine unless you enable sync.

Can I contribute?

Absolutely — Sunday is Apache-2.0. See the contribution guide and the GitHub repo. Good first issues are labeled for newcomers.

Who builds Sunday?

Sunday is built by Vivek Bartwal. Reach out via the support channels — WhatsApp, email, or LinkedIn.

Glossary

Agent
An autonomous worker that plans and executes a coding task: reading files, editing code, running commands, and reporting results.
Orchestrator
The planning layer that decomposes your prompt into subtasks, assigns agents, and merges their results.
Swarm
A set of parallel agents working on cards of a Kanban board generated from a single prompt.
Second Brain
Sunday's persistent memory store: your preferences, conventions, and project facts, recalled automatically per task.
Artifact
A rendered output produced by an agent — HTML preview, diagram, or document — shown in the Artifacts panel.
Mission Control
The dashboard listing every running agent with live logs and pause/resume/stop controls.
Best-of-N
A mode where N agents solve the same task with different strategies so you can compare and pick the winner.
sundayd
The local background daemon that owns scheduled tasks and long-running agents independent of the UI.
Gateway
Sunday's hosted service: authentication, quotas, streak tracking, and provider routing for zero-config inference.
BYOK
"Bring your own key" — using your personal OpenRouter/Groq API key instead of the hosted gateway quota.
Streak
Consecutive days of coding activity. Longer streaks earn bonus daily AI requests.
Takeover mode
Browser-agent feature letting you grab control of the automated browser mid-task, then hand it back.
Conflict detection
The mechanism that prevents two parallel agents from overwriting each other's edits to the same code region.

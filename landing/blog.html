Introducing Sunday: the open-source AI code editor

October 9, 2026 · by Vivek Bartwal · 6 min read

Today we're releasing the first public beta of Sunday — an open-source, AI-native code editor built as a VS Code fork, free to use with 200 AI requests per day and zero configuration.

Why another AI editor?

AI coding assistants have converged on the same interaction model: one chat panel, one agent, one task at a time. That model breaks down the moment your task is bigger than a single file. Real software work is parallel — the frontend, the API, the tests, the migration script — and forcing it through a single sequential agent is like hiring a team and only letting one person work at a time.

Sunday starts from a different premise: development is a team sport, and your team can be agents. Describe the goal once, and Sunday's orchestrator decomposes it into parallel subtasks, runs agents against them simultaneously, detects conflicts between their edits, and verifies the merged result. You manage the plan; agents do the work.

Why a fork, not an extension?

We started with an extension (sunday-agent, still available as a standalone VSIX). But the features that matter most — a persistent daemon for scheduled tasks, workbench-level agent panels, cross-agent conflict detection, deep memory integration — need to live below the extension API. Forking VS Code gives us the surface area to build agent-driven development as a first-class citizen rather than a bolt-on.

What's in the beta

  • Parallel agents with bounded pools and conflict detection
  • Second Brain persistent memory across sessions
  • Browser agent with live screencast and takeover mode
  • One-prompt swarm — one prompt becomes a Kanban board of agents
  • Coding streaks with Streak Freeze, Vacation Mode, and quota bonuses
  • Zero-config free tier — sign in with GitHub/Google/Microsoft, get 200 req/day
  • Beta auto-updates through the prerelease channel

Open source, for real

Sunday is Apache-2.0. The IDE, the extension, and the daemon are all public at github.com/Vivek492005/Sunday. We believe the tool that writes your code should be auditable by you — especially when agents are editing files and running commands on your machine.

What's next

The beta is the foundation. Next come quests and achievements, ranks and leagues, the JetBrains plugin, and the stable 1.0. But the most important thing right now is feedback: open an issue, tell us what breaks, and help shape what Sunday becomes.

Download Sunday v1.0.0-beta.1 for Windows, macOS, or Linux — free, no API key required.

How parallel agents work under the hood

October 9, 2026 · by Vivek Bartwal · 8 min read

Parallel agents are Sunday's signature feature — and the one most likely to be misunderstood. This post explains the actual architecture: how tasks get decomposed, how agents stay out of each other's way, and what the verifier does.

The problem with naive parallelism

Give five agents the same repo and one shared instruction, and you get five agents stepping on each other: duplicate work, conflicting edits, and a merge nightmare. Parallelism without coordination is worse than sequential work. Sunday's answer is a four-stage pipeline: decompose → scope → execute → verify.

Stage 1: Decompose

The orchestrator (a planning pass, not a worker) reads your prompt plus project context — open files, repo structure, Second Brain memories — and produces a task tree. Each node has a goal, acceptance criteria, and a file scope. The tree is the contract: agents don't negotiate with each other, they fulfill their node.

Decomposition is context-centric. A node working on the auth module gets the auth files and the API contract — not the entire repo. This keeps each agent's context small, focused, and cheap.

Stage 2: Scope and schedule

Nodes are scheduled onto a bounded pool of agent workers. The bound matters: unbounded parallelism thrashes your machine and burns quota. Defaults are 2 (Basic), 3 (Smart), and 4 parallel (Pro). Independent nodes run concurrently; dependent nodes wait — the scheduler tracks the dependency graph so a node blocked on another node's output doesn't start early and guess.

Stage 3: Execute with conflict detection

Each agent works in its own context with its declared file scope. A conflict-detection layer watches edit regions: if two agents target overlapping regions of the same file, one is paused until the other commits its change, then the paused agent re-reads and continues. This is the piece most "multi-agent" demos skip — and the piece that makes parallel agents actually usable on real codebases.

Stage 4: Verify

A single verifier agent reviews the merged result against every node's acceptance criteria. It runs the tests, checks the diffs, and either approves or sends specific nodes back for rework. Nothing reaches your working tree until verification passes — you review one coherent diff, not five partial ones.

When not to parallelize

Honest note: not every task benefits. A single focused bug fix in one function is often faster with one agent — decomposition overhead isn't free. Sunday's orchestrator estimates parallelizability and will tell you when a task is better run solo. The chaining tutorial covers how to think about this in practice.

Coding streaks: gamifying consistency

October 9, 2026 · by Vivek Bartwal · 5 min read

The most controversial feature in Sunday's beta isn't an agent feature at all — it's a fire icon in the status bar. Here's why we built coding streaks into a code editor, and how we tried to make them humane.

Consistency beats intensity

Every experienced developer knows the pattern: the developers who improve fastest aren't the ones who pull heroic 12-hour sessions — they're the ones who show up every day. Ninety minutes daily beats a monthly hackathon for skill-building, every time. But "show up every day" is a hard habit to maintain without feedback. Streaks are that feedback: a visible, honest record of showing up.

Designed to be humane

Streak systems have a dark side — they punish rest, travel, and life. We built two safety nets from day one:

  • Streak Freeze: bank freezes that preserve your streak through missed days. Earn them through consistent weeks, spend them when life happens.
  • Vacation Mode: going away? Pause streak counting entirely for a planned break. No penalty, no guilt, no gaming the system.

A streak system without rest mechanics is a burnout machine. We'd rather you take the vacation.

Streaks pay real rewards

Vanity metrics are cheap; we wanted streaks to have teeth. So streak milestones pay out in the currency developers actually value — AI quota:

  • 7-day streak: +100 requests/day on top of your plan
  • 30-day streak: +500 requests/day on top of your plan

Your most consistent weeks become your most powerful weeks. The better your habit, the more agent firepower you have to build with.

What's next for engagement

Streaks are phase one. The roadmap adds quests (guided challenges for learning agent workflows), achievements (milestones like your first swarm), and eventually ranks, squads, and seasonal leagues. The philosophy stays the same: reward consistency, respect rest, and make every reward real.

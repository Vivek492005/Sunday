Parallel agents

Core

What it is. Instead of one AI assistant working through your task step by step, Sunday spins up multiple agents that work on different parts of the same task simultaneously — then merges their results.

How it works. When you describe a task, the orchestrator decomposes it into independent subtasks and assigns each to an agent from a bounded pool. Agents run in isolated contexts with their own file-edit scopes. A conflict-detection layer watches for overlapping edits; when two agents touch the same region, one is paused and the other finishes first. A single final verifier agent reviews the merged result for consistency before anything is committed to your workspace.

Why it matters. Large refactors, multi-file features, and test+implementation pairs are embarrassingly parallel. Parallel agents routinely cut wall-clock time by 2–4x on decomposed tasks, and the bounded pool means your machine never thrashes — you set the cap (default 4 on Pro, 2 on Basic).

Tip: Tier limits control how many agents run at once — Free: 1 agent, Basic: 2 sequential, Smart: 3 sequential, Pro: 4 parallel. See pricing in the docs.

Hierarchical orchestration

Core

What it is. The intelligence behind parallel agents: a planning layer that breaks your goal into a tree of subtasks, where each node gets exactly the context it needs — no more, no less.

How it works. The root planner reads your prompt plus the relevant project context (open files, repo structure, Second Brain memories) and produces a task tree. Each child agent receives a scoped brief: its goal, its files, and its constraints. Children can spawn their own sub-agents for nested work. Results bubble up the tree, with each parent verifying its children's output against acceptance criteria before marking the node complete.

Why it matters. Context is the scarcest resource in agent coding. Dumping your whole repo into every agent wastes tokens and degrades quality. Context-centric decomposition keeps each agent focused, which means fewer hallucinations, lower cost per task, and results you can actually review node by node.

Second Brain

Memory

What it is. Persistent memory for your agents. Sunday remembers your preferences, project conventions, and past decisions across sessions — so you stop repeating yourself.

How it works. As you work, Sunday extracts durable facts ("prefers pnpm over npm", "API base URL lives in env", "always writes tests for utils") into a local memory store. Every new agent task starts with a memory lookup: relevant facts are injected into the agent's context automatically. You can view, edit, and delete memories from the Second Brain panel, and nothing leaves your machine unless you enable cloud sync.

Why it matters. The difference between a tool and a teammate is memory. With Second Brain, your tenth session with Sunday is noticeably better than your first — conventions stick, style matches, and "like last time" actually works.

Browser agent

Automation

What it is. An agent that can see and act on the web: it drives a real browser, watches the page through a live screencast, and clicks, types, and scrapes like you would.

How it works. The browser agent runs a controlled Chromium session in a sandbox. You see exactly what it sees via the live screencast panel. Takeover mode lets you grab control mid-task — move the mouse or type, and the agent pauses and watches, then resumes when you hand back control. Every session is recorded with media, so you can replay what the agent did and audit every action.

Why it matters. Half of real development work lives in the browser: checking docs, testing deployments, filing issues, verifying UI. The browser agent closes that loop without you context-switching, and the recording gives you a verifiable trail instead of a black box.

Availability: Browser sessions are tier-limited — Free has no browser access, Basic gets 5 sessions/day, Smart 15/day, Pro unlimited.

One-prompt swarm

Core

What it is. Type one prompt — "add user authentication with tests" — and watch it become a live Kanban board of parallel subtasks, each worked by its own agent.

How it works. The swarm planner converts your prompt into cards on a Kanban board: columns for queued, in-progress, in-review, and done. Each card is a scoped agent task with its own context. You can drag cards to reprioritize, click any card to see its agent's live log, pause individual cards, or add new cards mid-run. Dependencies between cards are tracked automatically — a card blocked on another waits instead of guessing.

Why it matters. Big tasks are easier to trust when you can see the plan. The Kanban view turns agent work from a mysterious loading spinner into a project you can manage, with the same mental model teams already use.

Artifacts

Output

What it is. When agents produce something worth looking at — an HTML mockup, a diagram, a document — it opens in a dedicated Artifacts panel as a live, interactive preview instead of a raw file.

How it works. Agents can emit artifacts in supported formats (HTML, SVG, Markdown). The Artifacts panel renders them live: HTML previews run in a sandboxed frame, diagrams render from generated SVG, documents render as formatted Markdown. Each artifact is versioned — when the agent iterates, you can flip between versions and diff them. One click exports any version to your workspace as a real file.

Why it matters. Reviewing agent output as files is slow. Artifacts let you see what the agent made the way it was meant to be seen, iterate visually ("make the header darker"), and only commit to disk when you're happy.

Mission Control

Observability

What it is. One dashboard showing every running agent: what it's doing, its live log, its token usage, and controls to pause, resume, or stop it.

How it works. Every agent registers with the local daemon (sundayd) on spawn. Mission Control lists them with real-time status, current subtask, elapsed time, and request counts. Expanding an agent streams its log. You can pause an agent mid-run to inspect its working tree, resume it, or kill it — killed agents leave their partial work in a recoverable state.

Why it matters. Parallel agents without observability are chaos. Mission Control is the difference between "something is running" and "I know exactly what's running, what it costs, and I can stop any of it."

Best-of-N

Quality

What it is. For tricky problems, Sunday tries N different approaches in parallel — then shows you the candidates side by side so you pick the winner.

How it works. Enable Best-of-N on any task (or set it as default for refactors). The orchestrator spawns N agents with deliberately varied strategies — different decompositions, different libraries, different trade-offs. Each produces a complete solution. The comparison view shows diffs, test results, and each agent's rationale. You pick a winner, or merge pieces from several.

Why it matters. The first solution an AI produces is rarely the best one. Best-of-N trades compute for quality on the tasks where quality actually matters — architecture decisions, tricky refactors, API design — and the side-by-side view makes the trade-offs legible.

Scheduled tasks

Automation

What it is. Cron for agents. Describe a recurring job in plain language — "every morning, check test health and report" — and Sunday runs it on schedule, even when the IDE is closed.

How it works. Scheduled tasks are defined with a natural-language prompt plus a cron expression (or a preset like "daily at 9am"). The daemon wakes the task, spins up an agent with the saved context, runs it, and delivers the result — to a notification, a file, or your inbox depending on configuration. Full run history is kept, so you can see what ran, what it found, and what it changed.

Why it matters. Agents are most valuable when they work while you don't. Nightly dependency checks, morning standup summaries, weekly changelog drafts — the boring-but-important work happens on autopilot.

Coding streaks

Gamification

What it is. Daily coding streaks that reward consistency: code every day to build your streak, and longer streaks earn bonus AI requests on top of your plan quota.

How it works. Any day with meaningful editor activity counts toward your streak, shown as a fire indicator in the status bar. Life happens, so two safety nets exist: Streak Freeze (bank freezes that preserve your streak through missed days) and Vacation Mode (pause streak counting for a planned break). Streak milestones pay out: a 7-day streak adds +100 requests/day to your quota, and a 30-day streak adds +500/day.

Why it matters. Consistency beats intensity in skill-building. Streaks turn "I should code today" into a visible, rewarding habit — and the quota bonuses mean your most consistent weeks are also your most powerful.

Zero-config free tier

Onboarding

What it is. Install Sunday, sign in with GitHub, Google, or Microsoft, and you're building with real AI models in under a minute. No API keys, no provider accounts, no configuration.

How it works. The Sunday hosted gateway holds provider keys server-side and issues you a session on sign-in. The free tier includes 200 AI requests per day — real models, not a trial, with no credit card and no expiry. If you outgrow it, paid tiers raise the limits; if you prefer your own keys, BYOK (bring your own key) for OpenRouter or Groq is supported and bypasses Sunday quotas entirely.

Why it matters. API-key setup is the number-one reason developers abandon AI tools before trying them. Zero-config removes the entire funnel between "download" and "first agent task" — which is exactly where adoption is won or lost.

Auto-updates

Platform

What it is. Sunday checks for updates on startup and installs them in one click. Beta users automatically receive prerelease builds through the beta channel.

How it works. On launch, the updater queries the release feed. Stable installs only ever see stable releases; beta installs see the latest beta build. When an update is available, a single click downloads and applies it — no manual re-downloads, no installer hunting. The beta channel means testers get fixes within hours of a release, not weeks.

Why it matters. An AI coding tool that falls behind is a liability — models, providers, and agent strategies evolve weekly. Auto-updates keep every install current with zero maintenance burden on you.

# Sunday Hosted Gateway — Load Test Report

**Date:** 2026-10-08
**Target:** `https://sunday-final-ide.onrender.com` (Render free tier, Singapore)
**Script:** `scripts/load-test-gateway.mjs`
**Duration:** 4.1 minutes
**Result:** ALL CHECKS PASSED ✅

## Methodology

Respectful load test against the live free-tier service. Five phases:

1. **Warmup** — 10 sequential `GET /health` (measures cold-start vs warm latency)
2. **Concurrency ramp** — 1, 5, 10, 25, 50 concurrent connections to `GET /health`, 30s each (p50/p95/p99, error rate)
3. **Sustained** — 10 concurrent `GET /updates/check` for 60s (verifies 10-min cache)
4. **Rate limit** — 30 rapid `POST /auth/session` with invalid token (verifies 20 req/min/IP bucket, 429 + Retry-After)
5. **Auth gate** — `GET /v1/models` without auth (expects 401)

`/v1/chat/completions` was deliberately NOT tested (costs real provider credits).

Safety: abort on 10 consecutive 5xx/network failures or 30s unresponsiveness; 10-min total budget.

## Findings & Recommendations

### Capacity
- **Comfortable:** ~10 concurrent users (p95 < 500ms)
- **Acceptable:** up to ~25 concurrent (p95 ~1s)
- **Degraded but functional:** 50 concurrent (p95 ~2s, zero errors)
- The gateway **never crashed or errored** under any tested load — it slows down instead of failing, which is the right failure mode.

### Bottleneck
Single-threaded Node.js on Render's free-tier CPU. Latency scales linearly with concurrency beyond ~10 connections. This is expected and fine for the current free-tier launch (200 req/day quota means sustained concurrency will be low).

### Before scaling beyond free tier
1. **Render paid instance** ($7/mo) — 2-4x the CPU, removes spin-down cold starts (~2s penalty today)
2. **The 200 req/day quota** is the real capacity control, not concurrency — at expected launch traffic, concurrency will rarely exceed 5
3. **No changes needed** to the gateway code based on these results

### Notes
- Cold start (~2.3s) only affects the first request after inactivity; consider a cron ping every 10 min to keep warm if UX matters
- `/updates/check` cache verified working — GitHub API is hit at most once per 10 min regardless of client traffic
- Rate limiter (20 req/min/IP on `/auth/*`) verified with correct 429 + Retry-After behavior
